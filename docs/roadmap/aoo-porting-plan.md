# aoo 整體管理模組移植計畫

- 狀態：已採用（Key User，2026-11-10，AP1–AP8 依草稿建議確認）
- 依據：`legacy/utf8/tiptop/aoo/4gl`（70 支）、`legacy/utf8/topcust/coo/4gl`（11 支客製）、各主要資料表 `.sch`
- 相關：CLAUDE.md 開發流程、ADR 0007（多營運中心）、ADR 0011（報表）、ADR 0012（異動記錄）、ADR 0013（標準功能鈕）

## 1. 目標

把 TipTop aoo（整體管理）模組的作業全部移植到 TTRS（Rust），保留業務行為。每支程式都照 CLAUDE.md 的六個步驟
（萃取 → 規格 → Red → Green → 對照 → 檢查），並具備 ADR 0013 的標準功能鈕。
不是每支 4GL 都要一對一重寫：有些由 TTRS 既有機制取代（異動記錄、報表、營運中心切換），有些屬於其他模組，在該模組移植時一起做。

## 3. 程式清單與處理方式

處理方式：**移植**＝照流程移植；**合併**＝併入另一支 TTRS 作業；**取代**＝由 TTRS 既有機制取代、不另寫程式；
**轉模組**＝屬於其他模組，該模組移植時再做；**待確認**＝需 Key User 決定。
規模依 4GL 行數與表數粗估：S（< 800 行、單表）、M（800–1,500 行或單頭單身）、L（> 1,500 行或跨表規則多）。
有 topcust 客製者以客製為準（標 ★）。

## 4. 每支程式的完成定義

1. 規格（`specs/features/aoo/*.feature`）經 Key User 確認，含 ADR 0013 的標準功能鈕與例外。
2. legacy-map（`docs/legacy-map/aoo.yaml`）列出相關表每個 `.sch` 欄位，並標 `scope`（system／group／plant）。
3. domain → app → infra → api → web 全部完成；記憶體與 PostgreSQL 跑同一份規格。
4. 權限：`PORTED_PROGRAMS`、起始資料 migration（ADMIN 全部功能）、`authorization.feature` 對照表。
5. 三語翻譯、資料表 COMMENT、異動記錄觸發器（ADR 0012）、確認欄位（ADR 0013 SA9）。
6. `make check` 與 `make bdd-pg` 全綠，瀏覽器驗收。

## 6. 確認事項（皆採建議）

- **AP1　使用率。** 建議先以唯讀方式從 TOPTEST 統計各程式的使用紀錄（zu_file 程式使用、azo 修改記錄），
  一年內沒有使用的程式改為「不移植」。需要您同意連 TOPTEST（只讀、只連測試區）。
- **AP2　批次順序。** 建議照本文件 1 → 8；若料號自動編碼較急，批次 5 可提前到批次 2 之後。
- **AP3　自定義公式（批次 6）。** 正式區是否使用 aooi500–502？沒有使用就不移植。
- **AP4　資料中心拋轉（批次 7）。** 是否仍需要集團中心、資料拋轉？需要的話先寫 ADR。
- **AP5　簽核（批次 8）。** 簽核改用 TTRS 工作流（藍圖既定方向），aooi010、aooi020 的資料轉入工作流設定；各單據的簽核作業隨單據模組移植。
- **AP6　JavaMail（aooi998、aooi999）。** 改用環境變數設定 SMTP 即可，或要保留畫面維護？
- **AP7　歷史報表（aooq050、aooq051）與程式使用率分析（aoor010）。** 是否保留？
- **AP8　aooi080 碼別。** 併入既有的分類碼維護，用類別切換（建議），或維持獨立作業？
