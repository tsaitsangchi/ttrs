TipTop GP → Rust 全端 · 總計畫 v1 · 2026-10-30

TTRS 移轉藍圖

把鼎新 TipTop ERP（Genero 4GL＋Oracle）移轉為 Rust 全端系統。保留業務行為、不逐行翻譯，並把 AI 同時用在「怎麼開發」與「系統能做什麼」兩件事上。

24 個月總時程估算（Phase 0 盤點後校正）
8 個階段盤點、平台、主檔、供應鏈、製造、財務、報表與 AI、上線
4–6 人核心團隊＋AI agent，另需各模組 Key User
126目前 BDD 情境（記憶體與 PostgreSQL 皆通過）

時程與人力為規劃假設。TipTop 原始碼目前只匯入 azz 模組的 2 支程式（p_zz、p_zta），實際程式數、客製數與使用率要在 Phase 0 完整匯入後才能定案，屆時重排本表。

設計原則

AI 世代的 ERP 長什麼樣子

傳統 ERP 把規則藏在程式裡、把結構藏在資料庫裡，只有人能看懂。新系統的每一層都要讓人和 AI 都讀得懂、改得動、查得到。下面 8 條是所有階段共同遵守的原則，狀態標示目前專案的進度。

規格是唯一需求來源

已採用

業務規則寫成中文 Gherkin，Key User 確認後才實作。規格同時是需求、驗收測試與 AI 的工作說明，取代散落的口頭需求與 4GL 註解。

結構與說明都是程式碼

部分完成

資料表只由 migration 變更（不在畫面建表）；表與欄位的命名、說明放在版控檔案，跟著 PR 審查。make check 檢查新欄位必須有說明。

語意層讓 AI 看懂資料

已起步

資料字典＋TipTop 對照目錄（目前 161 表、1,633 欄位）＋規格，組成系統的語意層。AI 查詢、寫報表、移植作業都依賴它，而不是去猜 zx07 是什麼。

API 優先，Agent 可呼叫

待做

每個 use case 都是有 OpenAPI 描述的 API，畫面、PDA、外部系統共用。另提供 MCP 伺服器，讓 AI agent 在使用者權限內查資料、擬單據。

人在迴路，AI 不直接過帳

待做

AI 可以建議、填草稿、找異常，但確認、過帳、核准一律由人按下。所有 AI 產生的異動都標記來源並寫入稽核紀錄。

全面多語言

已採用

介面用 Fluent 翻譯檔、業務資料用 <資料>_text 表（ADR 0005）。繁中、英文、簡中三語同步，make check 擋漏翻。

可觀測、可稽核

待做

每筆業務異動留事件紀錄（誰、何時、改了什麼、來自人或 AI），API 有追蹤與指標。取代 TipTop 分散的 azo、zs、zu 紀錄檔。

安全是預設值

部分完成

單一 schema＋plant_id，以 PostgreSQL Row-Level Security 隔離營運中心。AI 查詢只走唯讀副本並套用同一套權限。TTRS 不連 TipTop 正式庫。

目標架構

由上到下的系統分層

延續 ADR 0001：Rust 分層架構、HTTP API 是唯一入口。新增的是 AI 層與幾個取代 TipTop 共用設施的服務（工作流、背景作業、報表）。

使用者體驗

Dioxus 一份程式碼輸出 Web、桌面（取代 GDC）、倉庫 PDA。每個畫面內建 AI 助手面板：解釋欄位、依文件填草稿、回答「這張單為什麼卡住」。

API

Axum REST＋OpenAPI 給畫面與外部系統；MCP 伺服器 把同一批 use case 包成 agent 工具，強制套用呼叫者的權限。

應用服務

各作業的 use case；共用服務取代 TipTop 設施：工作流與通知（gaf/gag/gah）、背景作業（p_cron、gde）、報表（CR、zaw/zaa）、文件附件（gca/gcb）。

領域規則

純 Rust，無 IO；金額數量一律 Decimal；錯誤碼是穩定 API。這層是規格的直接對應，也是 AI 最常修改的地方。

資料

PostgreSQL 單一 schema＋plant_id＋RLS；事件／稽核表記錄所有異動；唯讀副本給 BI 與 AI 查詢，不影響交易效能。

AI 層

LLM 閘道（模型可替換、記錄每次呼叫、遮罩個資）；語意層（資料字典、對照目錄、規格、SOP）；檢索（規格與說明文件）；自然語言查詢（只對唯讀副本、套 RLS）；文件擷取（PDF／掃描單據 → 草稿）。

移轉與整合

legacy-etl：依 legacy-map 從 Oracle 匯出、轉換、驗證；Golden Master 比對：同一批 TOPTEST 資料在新舊系統跑出相同結果。對外 EDI／API 於供應鏈階段補上。

移植生產線

每支 TipTop 程式走同一條流程

TipTop 的程式數以千計，靠人一支支讀 4GL 不可行。生產線讓 AI 負責大量的閱讀、草擬與實作，人把關三個關卡：規格確認、程式審查、新舊比對。紅框是關卡。

盤點與排序

依使用紀錄（zu、azo、gbq）與客製覆寫排出移植順序，決定哪些程式不移植。

AI 統計分類PO 決定範圍

AI 能力

AI 用在兩個地方

開發端的 AI 讓移植變快；使用端的 AI 讓新系統比 TipTop 更好用。使用端功能在交易模組穩定後才上，而且都遵守「AI 建議、人確認」。
