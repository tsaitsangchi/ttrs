# ADR 0013：維護作業的標準功能鈕

- 狀態：已採用（Key User，2026-11-10，SA1–SA9 依草稿建議確認）
- 相關：ADR 0004（Material 3 版面）、ADR 0006（權限：功能代號）、ADR 0011（報表與列印）、ADR 0012（異動記錄、資料有效）

## 背景

Key User 要求（2026-11-10）：**此專案所有的維護作業都必須有新增、修改、刪除、查詢、列印、匯出 Excel、上筆、下筆、
第一筆、末一筆、失效、複製等基本功能鈕。**
同日補充：**所有維護作業都有「確認」功能鈕，此「確認」功能鈕包含「確認」與「取消確認」。**

TipTop 的做法（萃取）：各作業的功能列（ring menu）由 4fd 與 `cl_set_act_visible` 決定，常見的功能代號為
insert、modify、delete、query、output（列印）、exporttoexcel、first、previous、next、last、jump、invalid（失效）、
reproduce（複製）；上下筆、跳筆在所有單檔作業都有（`cl_navigator_setting`），但 output、exporttoexcel、invalid、reproduce
並非每支作業都有（例如 aooi101 單位、axmi110 產品分類是多筆表格，沒有上下筆與複製）。

## 決策

### 1. 共用功能列元件

新增 `components/toolbar.rs` 的 `MaintenanceToolbar`：固定順序
**查詢、新增、修改、複製、刪除、確認／取消確認、失效／啟用、列印、匯出 Excel、異動記錄**，下方一列為**第一筆、上一筆、下一筆、最後一筆、跳至第 N 筆**
（現有 `RecordNav`）。各作業只提供動作的處理函式，不再各自排按鈕，版面與圖示一致。

### 2. 確認事項（皆採建議）

- **SA1. 適用範圍。** 建議套用於上表所有作業。以下不算維護作業，不套用：舊系統對照（唯讀查詢）、選單維護（樹狀編輯）、登入與密碼畫面。
- **SA2. 多筆表格式作業的上下筆**（單位、產品分類、分類碼、部門、員工）。TipTop 這類作業沒有上下筆。
  建議仍提供：第一筆／上一筆／下一筆／最後一筆移動「目前選取列」，跨頁時自動換頁；修改、複製、失效、刪除都作用在選取列。
- **SA3. 列印、匯出 Excel 的內容。** 建議每支作業都提供「清單報表」：欄位＝該作業清單（或單筆畫面主要欄位），
  範圍＝目前查詢條件（沒查詢時為全部），PDF 與 XLSX 用共用的通用版面（ADR 0011 的 Typst／rust_xlsxwriter），
  不必每支作業各寫範本。TipTop 有專屬報表版面的作業（如部門 aooi030、料件 aimr100）再另寫專屬範本。
  權限沿用功能代號 output、exporttoexcel，筆數上限 5,000（ADR 0011 RP6）。
- **SA4. 失效。** 建議凡有「資料有效」的主檔都提供失效／啟用（ADR 0012 標準欄位）。
  下列資料沒有資料有效的概念，建議列為例外，以刪除代替：
  | 作業 | 原因 |
  |---|---|
  | 程式執行權限 p_zy、使用者特殊權限 p_zxw | 權限設定列，失效等同移除權限 |
  | 資料字典 | 描述資料表結構，跟著資料表存在 |
  | 程式 p_zz | TipTop zz_file 沒有有效碼；不用的程式改由權限控制 |
- **SA5. 複製。** 建議所有主檔都提供複製（輸入新鍵值，其餘欄位帶入，資料所有者改為目前使用者、狀態回到新增時的狀態）。
  例外：資料字典（鍵值是資料表，不能複製）。
- **SA6. 沒有權限的按鈕。** 建議維持 ADR 0006 AQ13：沒有該功能權限時**隱藏**按鈕；有權限但目前不可用（例如沒有選取資料）時**顯示為停用**。
- **SA7. 功能代號與起始資料。** 每支作業的程式資料（default_actions）補齊 query、insert、modify、delete、reproduce、invalid、
  output、exporttoexcel、history，並以新 migration 給 ADMIN；同時加入 `authorization.feature` 對照表。
- **SA8. 實作順序。** 建議：先做共用元件與通用清單報表（以料件、料件分群試做），再依作業逐支補齊，
  每支作業補一份 `*_report.feature`（列印／匯出）與缺少功能的情境。

### 3. 「確認」功能鈕（SA9）

TipTop 的做法（萃取）：有確認流程的作業以功能 confirm（確認）、notconfirm（取消確認）切換資料的確認狀態，
例如 aimi100 料件的資料有效碼 imaacti P→Y、狀態碼 ima1010 0→1（item_maintenance.feature IM-16～IM-18、IM27）。
目前已移植的主檔中**只有料件 ima_file 有確認狀態**；其餘資料表只有資料有效碼（xxxacti，Y/N），沒有確認欄位：

| 作業 | 資料表 | 確認相關欄位 |
|---|---|---|
| 料件基本資料 aimi100 | ima_file | imaacti（P 處理中／Y 已確認／N 無效）、ima1010 狀態碼 |
| 料件分群 aimi110 | imz_file | 只有 imzacti（Y/N） |
| 單位 aooi101、部門 aooi030、員工 aooi040、分類碼 aooi300 | gfe／gem／gen／azf_file | 只有 xxxacti（Y/N） |
| 產品分類 axmi110、營運中心 aooi901 | oba／azp_file | 沒有有效碼 |
| 使用者 p_zx、權限類別 p_zw | zx／zw_file | 只有 xxxacti（Y/N） |

功能列做法（已實作於共用元件）：一個按鈕依目前這筆的狀態顯示「確認」或「取消確認」，分別檢查功能 confirm、notconfirm。

確認事項（皆採建議）：

- **SA9-1. 沒有確認狀態的作業怎麼確認？** 建議 TTRS 新增一組標準的確認欄位（同 ADR 0012 的標準欄位作法）：
  `confirmed`（已確認否）、`confirmed_by`（確認人）、`confirmed_at`（確認時間），放在「狀態」頁籤；
  新增時為未確認，按「確認」後為已確認，按「取消確認」回到未確認，都寫入異動記錄。料件沿用 TipTop 原有的資料有效碼與狀態碼。
- **SA9-2. 已確認的資料能不能修改、刪除？** 建議比照料件（aimi100 i100_u :2565-2600、i100_r :4274）：已確認的資料
  **可以修改、不可刪除**（須先取消確認，TipTop 9023）；失效／啟用不受確認狀態限制。
- **SA9-3. 未確認的資料能不能被其他作業引用？** 建議**可以**（只做狀態標示，不擋引用），避免現有資料轉入後全部無法使用；
  轉入的既有資料一律視為已確認。若您要「未確認不可引用」，各作業的檢查另案逐支加入。
- **SA9-4. 不適用的例外。** 建議與 SA4 失效的例外相同：程式執行權限、使用者特殊權限、資料字典、程式 不做確認。

## 影響

- 每支作業都需要補 output、exporttoexcel 的 use case 與 API；app 層新增通用的「清單報表」資料結構。
- 既有作業的畫面改用共用功能列，按鈕順序會統一調整。
