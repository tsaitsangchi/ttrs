# ADR 0005：通用多語言機制

- 狀態：已採用（2026-10-30）
- 範圍：所有畫面文字（crates/web）與所有需多語言的業務資料（domain / app / infra / api）

## 背景

目前多語言是一支一支設計的，已出現重複：

| 層 | 現況 | 問題 |
|---|---|---|
| 介面文字 | `crates/web/src/i18n.rs`：`t("繁中原文")`、錯誤代碼翻譯、側邊欄切換 | 翻譯寫在 Rust 陣列，翻譯人員要改程式；以繁中原文為鍵，同字不同義無法分開；漏翻沒有檢查 |
| 資料多語言 | 程式名稱（`program_name`）、表說明（`table_dictionary_text`）、欄位說明（`column_dictionary_text`）各自實作 | 語系檢核、退回繁中（L2）、長度檢核、API 形式、編輯畫面每支重寫 |

TipTop 的做法供參考：資料多語言是「每種資料一張語言表」（gaz 程式名稱、gat 表名稱、gaq 欄位說明）；
畫面標籤存在資料庫（p_per / gae_file，依程式、欄位、語言別），客戶可自行修改用詞；
錯誤訊息也存在資料庫（p_ze / ze_file）；使用者的語言別記在使用者資料。

## 決策

### 1. 語系

- 支援 `zh-TW`（預設、翻譯來源）、`en`、`zh-CN`；定義只有一份：`ttrs_domain::lang::Lang`。
- 舊資料語言別對照：TipTop `0`→`zh-TW`、`1`→`en`、`2`→`zh-CN`。
- 介面語系決定順序：網址 `?lang=` → 使用者設定（導入登入後）→ 瀏覽器記住的語系 → `zh-TW`。

### 2. 介面文字：Fluent 翻譯檔

- 翻譯放在 `crates/web/locales/<語系>/<範圍>.ftl`（Mozilla Fluent 格式，支援參數與複數），編譯時內嵌。
  翻譯人員只改 `.ftl`，不碰 Rust。
- 訊息 ID 規則（Fluent ID 不可含 `.`，以 `-` 分隔）：`<範圍>-<類別>-<名稱>`
  - 共用：`common-action-query`、`common-action-save`、`common-msg-loading`
  - 作業：`program-field-program-no`、`program-tab-print`、`dictionary-field-table-name`
  - 錯誤：`error-PROGRAM_ALREADY_EXISTS`（後綴為 API 錯誤代碼，與 `DomainError::code()` 一致）
- `zh-TW` 為完整來源；其他語系缺少的 ID 退回 `zh-TW`。
- 函式庫：採 `fluent-bundle` 0.16 自建載入（`crates/web/src/i18n.rs`，畫面統一經 `t()` / `tf()`）。
  評估過 `dioxus-i18n` 0.6：其翻譯函式依賴元件 context，無法用於元件外的錯誤訊息翻譯（api.rs），故不採用。
- 檢查（`make check` 的一部分）：
  - 三個語系的 ID 集合一致（缺漏即失敗），參數名稱一致
  - 已改用翻譯的畫面原始碼中不得出現中文字串（測試 `translated_pages_have_no_hardcoded_chinese`；
    資料值如 QBE 條件值以該行 `i18n-allow` 註記例外）；畫面完成翻譯後加入該測試的清單
- 錯誤訊息：API 照舊回傳 `code` 與繁中 `message`；前端以 `error-<code>` 翻譯，找不到時顯示伺服器訊息。

### 3. 資料多語言：每種資料一張語言表，規則共用

不採「單一通用翻譯表（實體類型、鍵值、欄位、語系、文字）」：無法設外鍵與型別限制，查詢（含 QBE 依名稱查）複雜且慢。

採用 TipTop 同樣的「每種資料一張語言表」，命名 `<資料>_text`，結構固定：

```
<資料>_text (
  <資料鍵值…>  REFERENCES <資料> ON UPDATE CASCADE ON DELETE CASCADE,
  lang         varchar(5) CHECK (lang IN ('zh-TW','en','zh-CN')),
  <文字欄位…>  varchar(<依 TipTop .sch>),
  PRIMARY KEY (<資料鍵值…>, lang)
)
```

共用的部分（不再各自實作）：

| 層 | 共用 |
|---|---|
| domain | `ttrs_domain::lang`：`Lang`、`DEFAULT_LANG`；各語言列實作 `LangText`（程式名稱 `ProgramName`、表說明 `TableText`、欄位說明 `ColumnText`），建構時做語系與長度檢核；`localized(texts, lang, 欄位)` 退回規則：指定語系 → `zh-TW` → 無（各欄位各自退回）；`normalize_text` 空白視為未填 |
| app | 讀取時一律回傳「指定語系的顯示文字」＋「所有語系清單」；寫入時一律依語系 upsert |
| api | 讀取：`?lang=` 決定顯示語系（未給為 `zh-TW`），回應含顯示文字與所有語系清單（程式 `names`、資料字典 `texts`）；寫入：`PUT …/names`、`PUT …/texts` 一次一個語系 |
| web | `MultilingualField` 元件：三語並列或頁籤，一次儲存；各維護畫面共用 |

既有的 `program_name`、`table_dictionary_text`、`column_dictionary_text` 結構已符合此規則，改為使用共用元件即可，不需改表。

### 4. 預留：客戶自訂用詞

TipTop 允許客戶在資料庫改畫面標籤。新系統先以翻譯檔為準；日後如需客戶自訂，
新增「標籤覆寫表」（訊息 ID、語系、文字），載入時覆寫翻譯檔的值，畫面寫法不用改。

## 實施步驟

1. 本 ADR 與 CLAUDE.md 規則 ✅
2. 介面文字改用 Fluent 翻譯檔＋缺漏檢查；程式維護、外框改用 ID ✅
3. 後端共用規則（`LangText`、`localized` 退回規則、API 慣例）；程式維護、資料字典改用（既有 BDD 全過；資料字典顯示語系與匯出退回 D9/D10 已確認）✅
4. `MultilingualField` 元件（`crates/web/src/components/multilingual.rs`，每語系一列、非預設語系空白時以繁中為提示）；程式維護以 `ProgramInput.names` 一次儲存三語名稱與報表抬頭，資料字典表與欄位說明改用 ✅
5. 其餘畫面（aimi100、首頁、資料字典）套用 ✅：新增 `dictionary.ftl`、`item.ftl` 與料件、資料字典錯誤代碼翻譯；全部畫面已列入 `translated_pages_have_no_hardcoded_chinese`

## 後果

- 每支新作業只需：畫面用翻譯 ID、補三語翻譯、多語言資料照 `<資料>_text` 規則並用共用元件。
- 翻譯檔成為需要維護的資產；缺漏檢查讓 `make check` 在漏翻時失敗。
- 既有 `i18n.rs` 的繁中原文鍵值（約 120 條）在步驟 2 轉成 ID。
